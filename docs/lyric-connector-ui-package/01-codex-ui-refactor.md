# Lyric Connector 桌面控制界面 UI/UX 重构任务

你是一名资深 Windows 桌面应用 UI/UX 设计师和前端工程师。请根据当前项目代码，对 Lyric Connector 的桌面控制窗口进行系统性的 UI/UX 重构。

> 参考设计图：`lyric-connector-ui-design.png`。设计图仅用于参考视觉语言和信息密度，不应机械照搬。**重要：设计图将左右两部分放在同一画面，但现有产品采用“音乐与歌词 / 悬浮窗口”两个 Tab；本次重构请保留这两个 Tab，不要擅自改为常驻左右双栏。**

## 一、项目背景

Lyric Connector 是一款 Windows 桌面工具：通过蓝牙连接 iPhone、读取 Apple Music 播放状态、获取歌曲名称与播放进度、自动或手动匹配同步歌词、支持导入 LRC，并在 Windows 桌面悬浮窗口显示歌词。现有控制界面有「音乐与歌词」「悬浮窗口」两个 Tab。

目标：在**保留现有技术栈和全部业务功能**的前提下，改善页面过长、控件松散、信息层级不清晰、空白过大及交互冗余等问题。不要重写蓝牙、音乐识别或歌词解析逻辑。

## 二、核心设计原则

- 采用轻量化、扁平化、紧凑但不拥挤的 Windows 桌面工具设计，不要做成 SaaS Dashboard。
- **避免过度 Card 化**：除了顶部深紫色播放器和确有必要的列表/预览表面，其余内容直接放在页面背景上，通过标题、留白、对齐、细分割线分区。
- 不添加大量白色圆角卡片、阴影、装饰性图标、彩色徽章或大面积渐变。
- 继续采用现有紫色品牌色；优化文字对比度、按钮主次关系和控件一致性。
- 减少说明性文字；保留首次使用时真正必要的帮助。
- 每个操作区域只突出一个主操作；避免多个同等视觉权重的紫色按钮。
- 尽量复用现有 UI 技术栈、组件、状态管理和事件处理，不引入大型依赖。
- 不删除功能，不改变业务行为，不做只有静态外观而无真实交互的控件。

## 三、先分析代码

1. 确认 UI 框架、渲染方式、主窗口与悬浮窗口之间的边界。
2. 定位主题样式、窗口布局、播放进度刷新、蓝牙设备发现/连接状态、歌词搜索与选择、LRC 导入、配置持久化逻辑。
3. 列出需要修改的组件和文件，确认哪些属于业务层、哪些属于 UI 层。
4. 用简短计划说明重构策略，然后直接修改代码；无需等待逐项确认。

## 四、整体布局

```text
┌───────────────────────────────────────────────────┐
│ Lyric Connector                                   │
│ 音乐在手机，歌词在桌面                              │
│ ┌───────────────────────────────────────────────┐ │
│ │ 爱是怀疑                         02:31 / 04:33│ │
│ │ Eason Chan · Apple Music                     │ │
│ │ ━━━━━━━━━━━━━──────────────                   │ │
│ └───────────────────────────────────────────────┘ │
│ 音乐与歌词         悬浮窗口                        │
│ ──────────                                        │
│ 当前 Tab 内容（必要时独立滚动）                    │
└───────────────────────────────────────────────────┘
```

- 固定顶部品牌信息、紧凑播放器和 Tab 导航；内容过长时只滚动主体区域。
- 避免嵌套滚动条和横向滚动。
- 默认窗口尺寸及最小尺寸下均无组件覆盖或裁切；兼容 Windows DPI 100%、125%、150%。
- 保留深紫色播放器作为主要视觉强调，建议约 72–90px 高（依实际布局微调）。
- 播放器显示真实歌曲名、歌手、来源、当前/总时长及进度条，长标题省略但可查看完整文本。
- 不添加不存在的播放控制能力，不伪造进度或连接状态。

## 五、音乐与歌词 Tab

### 设备连接

建议布局：

```text
设备连接                          已连接 · Apple Music
[iPhone · 简短设备名或 ID   ▼] [刷新] [连接/断开]
────────────────────────────────────────────────────
```

- 去除外层独立 Card，设备连接控件尽量一行放置。
- 优先使用友好设备名；无名称时缩短长 ID，完整 ID 仍可查看。
- 根据真实状态切换连接/断开按钮与状态文案；刷新时显示加载并避免重复提交。
- 连接指南不再长期占据主要空间：首次未连接可展开，连接成功自动收起，之后通过「连接帮助」重新打开。

### 歌曲与歌词

```text
歌曲与歌词                            来源：LRCLIB
歌曲名称                          歌手
[爱是怀疑                   ]      [Eason Chan         ]
[搜索歌词] [导入 LRC]
────────────────────────────────────────────────────
候选歌词列表
```

- 歌名与歌手双列排列，输入框整齐对齐；窄窗口可改成单列。
- 「搜索歌词」为主按钮，「导入 LRC」为次要按钮。
- 不另设包住整块表单的 Card。
- 未搜索时仅展示简短占位语，不出现约 200px 的空白框。
- 搜索中展示加载；成功显示候选列表；无结果提供导入入口；失败显示明确错误和重试。
- 每条候选尽可能展示歌曲名、歌手、时长、来源、同步时间戳状态；使用轻量列表行、细分隔线与选中背景，不要每条一张 Card。
- 「使用所选歌词」与选中状态关联，避免主操作冲突；当前正在使用的版本需明确标识。
- 如果原来支持自动匹配，则继续自动匹配；手动搜索、修改歌名、导入 LRC 是补充能力而非必经步骤。

## 六、悬浮窗口 Tab

采用标准桌面设置行：左侧标签、右侧控件、统一对齐基线、分组标题和细分割线。**不要将“文字样式”“歌词颜色”“背景与交互”分别包成大 Card。**

### 悬浮歌词

- 保留显示/隐藏功能，真实反映悬浮窗口状态。
- 可增加紧凑的歌词实时预览，但优先复用现有悬浮窗口/数据；若实现会引入不必要的状态同步复杂度，优先保证真实悬浮歌词的实时反馈。
- 不使用伪造歌词声称是实时播放内容。

### 文字样式

```text
文字样式
字体       [Microsoft YaHei UI             ▼]
字号       ─────●──────────────       16 px
当前行     [■] [#E4D7E7                ]
后续行     [■] [#B0A9C6                ]
──────────────────────────────────────────────
```

- 字体、字号、颜色全部采用统一标签列。
- 字号保留已有范围约束，显示 `px`；在可行情况下支持精确输入。
- 颜色预设从常驻多排色块改为紧凑色板/弹出选择器；HEX 值可编辑并校验。
- 颜色若能实时保存/应用，移除重复的「应用」按钮；否则保留清晰统一的提交机制。

### 背景与交互

- 保留现有背景不透明度及鼠标悬停、穿透、锁定等项目中实际存在的设置，不凭空添加假功能。
- 明确 `0% = 完全透明`、`100% = 完全不透明`；使用统一滑块宽度与百分比数值位置。
- 将辅助说明缩短为必要的一句话或 tooltip。

## 八、交互及性能

- 切换 Tab 不触发蓝牙重连、不丢失状态。
- 播放进度更新不要引发整个设置页不必要的重绘。
- 切歌时歌曲、歌手、歌词状态与播放器同步。
- 设置调整流畅，避免闪烁、布局抖动和不必要的全局渲染。
- 异步动作禁用重复提交，反馈放在对应操作区域附近，少用阻断式弹窗。
- 保留原有配置格式、持久化行为、键盘操作与无障碍标签。

## 九、实现约束

1. 不改变业务 API、蓝牙协议、设备发现逻辑、歌词同步/解析算法。
2. 不删除现有功能；不随意修改持久化格式。
3. 避免新增第三方依赖，避免 UI 样式影响独立的桌面歌词悬浮窗口。
4. 不过度抽象组件，也不重复实现业务事件处理。
5. 如果 UI 变化与业务冲突，优先保留业务功能。
